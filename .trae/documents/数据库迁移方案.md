## 数据库迁移方案

### 当前状况分析
- **存储方式**：IndexedDB（通过 Dexie.js）
- **问题**：数据仅存储在浏览器本地，换浏览器/设备无法访问
- **数据结构**：客户信息（Customer）和交易记录（Transaction）

### 推荐方案对比

#### 方案一：Supabase（强烈推荐）
**优点：**
- 开源免费，免费额度充足（500MB 数据库，1GB 文件存储）
- 提供 RESTful API 和实时订阅
- 内置用户认证系统
- 支持 TypeScript，类型安全
- 部署简单，无需后端服务器
- 数据可以在任何设备访问

**实施步骤：**
1. 注册 Supabase 账号并创建项目
2. 创建数据库表（customers, transactions）
3. 安装 `@supabase/supabase-js` 依赖
4. 创建 Supabase 客户端配置
5. 修改数据访问层（store）从 IndexedDB 迁移到 Supabase
6. 添加数据迁移脚本（将现有数据导出到 Supabase）

#### 方案二：Firebase Firestore
**优点：**
- Google 出品，稳定可靠
- 免费额度：1GB 存储，10GB/月流量
- 实时同步功能
- 离线支持
- 跨平台支持

**缺点：**
- 查询能力相对较弱
- 数据结构需要调整（NoSQL）

#### 方案三：自建后端 + PostgreSQL
**优点：**
- 完全控制数据和架构
- 适合有服务器的场景

**缺点：**
- 需要维护服务器
- 部署和运维成本高
- 需要处理认证、安全等问题

### 推荐实施方案：Supabase

**技术栈：**
- 数据库：Supabase PostgreSQL
- 认证：Supabase Auth（可选）
- API：Supabase RESTful API
- 前端：React + Zustand

**实施计划：**
1. 创建 Supabase 项目和数据库表
2. 安装 Supabase 客户端库
3. 创建 Supabase 配置文件
4. 修改数据访问层（保持 API 接口不变）
5. 添加数据迁移工具
6. 测试和验证

**预计工作量：**
- 配置 Supabase：30分钟
- 修改数据访问层：2-3小时
- 数据迁移工具：1小时
- 测试和调试：1-2小时

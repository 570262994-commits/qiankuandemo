## 无感云端存储方案实施计划

### 核心设计理念
- **无感使用**：用户无需注册登录，自动生成设备 ID
- **数据上云**：所有数据存储在 Supabase
- **数据隔离**：通过 device_id 实现多设备数据隔离
- **极简同步**：只需一个备份码即可在新设备同步数据

### 实施步骤

#### 1. 环境变量配置
- 创建 `.env` 文件（从用户获取 Supabase URL 和 Key）
- 创建 Supabase 客户端配置（不弹窗提示）

#### 2. 静默 ID 逻辑
- 创建 `src/lib/deviceId.ts`
- 应用启动时检查 localStorage 的 `anonymous_user_id`
- 如果没有，生成 UUID 并存储
- 提供获取和设置设备 ID 的方法

#### 3. 数据库表结构（Supabase SQL）
```sql
-- 客户表（增加 device_id）
CREATE TABLE customers (
  id BIGSERIAL PRIMARY KEY,
  device_id TEXT NOT NULL,
  name VARCHAR(50) NOT NULL,
  phone VARCHAR(11),
  credit_limit DECIMAL(10, 2) NOT NULL DEFAULT 0,
  payment_term INTEGER NOT NULL DEFAULT 30,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 交易记录表（增加 device_id）
CREATE TABLE transactions (
  id BIGSERIAL PRIMARY KEY,
  device_id TEXT NOT NULL,
  customer_id BIGINT NOT NULL,
  type VARCHAR(10) NOT NULL,
  amount DECIMAL(10, 2) NOT NULL,
  occurred_at TIMESTAMP WITH TIME ZONE NOT NULL,
  due_date TIMESTAMP WITH TIME ZONE NOT NULL,
  note TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 创建索引（包含 device_id）
CREATE INDEX idx_customers_device_id ON customers(device_id);
CREATE INDEX idx_transactions_device_id ON transactions(device_id);
```

#### 4. 数据访问层重构
- 创建 `src/lib/supabaseApi.ts`
- 所有查询自动带上 `device_id` 过滤
- 所有插入自动带上 `device_id`
- 保持原有 API 接口不变

#### 5. Store 层修改
- 修改 `customerStore.ts` 使用 Supabase API

#### 6. 设置页面（备份码功能）

- 显示当前设备 ID（备份码）
- 提供输入备份码的功能

#### 7. 应用入口修改

### 用户体验流程

1. **首次使用**：
   - 自动生成设备 ID
   - 数据自动存储到云端
   - 无需任何操作

2. **更换设备**：
   - 打开设置页面
   - 输入旧设备的备份码
   - 自动同步所有数据

3. **日常使用**：
   - 完全无感
   - 数据自动云端同步
